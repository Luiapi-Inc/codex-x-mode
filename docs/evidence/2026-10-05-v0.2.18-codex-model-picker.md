## Problem and root cause

Codex X Mode already exposed its packaged ChatGPT Web aliases through MCP, but MCP model listing is not the Codex host model picker. The user-level Codex configuration did not select the Codex X Mode Responses provider or a native `model_catalog_json`, so Desktop/CLI had no native `chatgpt-web/*` entries to select.

v0.2.18 adds a self-contained Codex catalog generator. It reads the installed Codex bundled model catalog with `codex debug models --bundled`, clones native metadata for the exact underlying packaged models, and rewrites only the public alias/display/priority/visibility fields. This keeps the generated schema aligned with the installed Codex version instead of vendoring a second model-schema snapshot.

The existing private Responses route remains authoritative. The provider is named `Codex X Mode` for display while the stable provider ID remains `custom_gpt_bridge` for compatibility. Provider credentials remain outside Git and are referenced through `CODEX_BRIDGE_PROVIDER_KEY`.
