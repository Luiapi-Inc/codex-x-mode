# v0.2.16 Codex MCP configuration evidence — 2026-10-05

## Requirement

Make the existing Codex X Mode plugin configure its MCP connection for Codex Desktop without starting a second bridge owner against the same private runtime config.

## Root cause

The v0.2.15 Codex compatibility configuration used bundled `mcp-stdio`. With the Secure Tunnel HTTP bridge already running from the same private config, a second stdio process exits fail-closed with:

```text
This configuration already has a running bridge
```

The runtime lock is intentional and must not be bypassed because two owners could duplicate worker/state handling.

## Configuration change

`.mcp.json` now configures Codex to reuse the existing execution-host bridge:

- transport: HTTP
- URL: `http://127.0.0.1:8240/mcp`
- bearer token environment reference: `CODEX_X_MCP_TOKEN`
- no bearer token or other secret is stored in the plugin package
- portable `mcp.json` retains bundled stdio for standalone local hosts where no bridge owns the config lock

The Mac user-level Codex configuration was independently registered with the same loopback URL and bearer-token environment reference.
