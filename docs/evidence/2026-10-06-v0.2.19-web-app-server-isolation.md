## Root cause

Read-only `codex debug models` on the same account exposed all three packaged public aliases: `chatgpt-web/5.6-sol`, `chatgpt-web/5.6-luna`, and `chatgpt-web/5.5`. The model was therefore not actually absent from the account.

v0.2.18 installs a user-level `model_catalog_json` so Codex Desktop can show the packaged `chatgpt-web/*` aliases. The headless Web app-server inherited that user-level Codex config. Its strict execution validator correctly asked Native Codex for the exact underlying model slug (`gpt-5.6-sol`), while inherited `model/list` returned the public aliases instead. Validation therefore failed before `thread/start`.

## v0.2.19 fix

Each headless Web app-server now runs with its own ephemeral `CODEX_HOME`. The process still receives the explicit private Responses provider settings and short-lived account access token through its environment/CLI overrides, but it no longer inherits the user's Desktop picker/provider configuration. The temporary Codex home is removed when the owned app-server closes and on launch failure.

This keeps the exact underlying-model validator strict instead of teaching it to accept alias contamination.
