# Codex X Mode v0.2.20 — Native Codex ownership and Codex X App acceptance

Date: 2026-10-06
Status: Source/package/runtime/private-plugin acceptance PASS; live inference/model-identity acceptance remains separate and unverified.

## Architecture correction

v0.2.20 restores the intended execution boundary for new work: Codex X Mode is the bridge/orchestrator while Native Codex owns authentication, `model/list`, reasoning metadata, `thread/start`, `turn/start`, inference, and terminal model identity. New Web tasks persist `execution_backend=codex_app_server` and do not route through SIWC, Subscription Sharing, `chatgpt_plan`, or a custom Responses provider. Legacy custom-provider handling remains reconciliation-only for already-persisted tasks.

## Codex X App surface

The package now owns a second MCP surface named `codex-x-app` and a bundled Skill named `codex-x-app-tool`. They are part of this repository and release package; runtime does not require the proprietary/external `codex-app-tools@openai-bundled` package.

Protocol baseline: `codex-cli 0.160.1`.

Endpoint: `POST /codex-x-app/mcp` using the existing `mcp_key` bearer boundary.

Native-backed tools in this release:

- `list_threads`
- `read_thread`
- `create_thread`
- `fork_thread`
- `send_message_to_thread`
- `set_thread_title`
- `set_thread_archived`
- `wait_threads`

The runtime owns one lazy managed `codex app-server --stdio` process and reuses it across Codex X App tool calls. No browser, daemon/proxy transport, external plugin, or second resident model runtime is required. `automation_update`, `set_thread_pinned`, and `handoff_thread` are intentionally not exposed because Codex CLI 0.160.1 does not provide matching native protocol primitives used by this package.
