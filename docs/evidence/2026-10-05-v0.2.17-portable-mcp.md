# v0.2.17 portable Codex MCP evidence — 2026-10-05

## Correction after v0.2.16 read-back

The v0.2.16 account release accepted the version update but read-back showed `.mcp.json` still contained the prior stdio configuration. The upload archive itself contained the requested HTTP `.mcp.json`.

Root cause: Agent Plugins 1.0 defines root `mcp.json` as the authoritative MCP configuration. The account packaging path derives/canonicalizes compatibility MCP configuration from that portable source, so changing only `.mcp.json` cannot override an existing root `mcp.json`.

## Effective package configuration

v0.2.17 changes root `mcp.json` to:

- `type=streamable-http`
- `url=http://127.0.0.1:8240/mcp`
- no literal Authorization header or other secret

The Codex compatibility `.mcp.json` uses the same URL with `bearer_token_env_var=CODEX_X_MCP_TOKEN`. User-level Codex configuration owns the machine-local bearer credential for the same endpoint.

Portable Agent Plugins explicitly forbid environment expansion in HTTP headers and treat header values as visible package data, so no bearer token is embedded in `mcp.json`.
