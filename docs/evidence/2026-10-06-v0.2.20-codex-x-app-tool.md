# Codex X Mode v0.2.20 — codex-x-app / codex-x-app-tool Evidence

Date: 2026-10-06
Branch: `feat/headless-web-route`

## Scope

v0.2.20 adds a second bundled MCP surface and Skill owned by Codex X Mode:

- MCP server/surface: `codex-x-app`
- Skill: `codex-x-app-tool`
- HTTP endpoint: `/codex-x-app/mcp`
- Python module: `bridge.codex_x_app`

This intentionally avoids the OpenAI-bundled/proprietary `codex-app-tools@openai-bundled` runtime package. The package ships its own adapter and Skill in this repository.

## Native Codex baseline

The baseline used for this release is:

```text
codex-cli 0.160.1
```

The implemented transport is a lazy managed Native Codex `app-server --stdio` process owned by the Codex X Mode runtime and reused across `codex-x-app` tool calls. This replaced the earlier daemon/proxy draft because a real no-inference probe against `daemon/proxy` timed out at `initialize`, while direct `app-server --stdio` passed `initialize + thread/list`.

## Exposed native-backed subset

`codex-x-app` exposes only operations backed by Codex CLI 0.160.1 app-server protocol primitives:

- `list_threads`
- `read_thread`
- `create_thread`
- `fork_thread`
- `send_message_to_thread`
- `set_thread_title`
- `set_thread_archived`
- `wait_threads`

The following are intentionally not exposed because the 0.160.1 native app-server protocol did not provide direct primitives during this release work:

- `automation_update`
- `set_thread_pinned`
- `handoff_thread`

## Guardrails preserved

- No browser, Playwright, Chromium, DOM automation, or `codex-chatgpt-web` dependency.
- No dependency on external Plugin/Skill/MCP runtime for `codex-x-app`.
- Native Codex remains the owner of app-server thread/turn operations.
- Custom provider/SIWC credentials are dropped from the native app-server environment.
- The existing `codex_app_server` execution backend name remains internal and is not the new MCP surface name.
- `codex-x-mode` and `codex-x-app` are separate MCP surfaces in `mcp.json` and `.mcp.json`.
